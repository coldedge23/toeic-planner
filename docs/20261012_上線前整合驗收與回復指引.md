## 已知限制與驗證邊界

- 未快取的Google字型片段在離線時無法下載，使用既有備援字型；作答與儲存正常。不保證首次未連網開啟能用。
- 路由有既有HydrateFallback警告；此次沒有新增應用程式執行錯誤。離線字型請求失敗已單獨記錄。
- Service Worker更新後，第一次重新載入可能仍顯示前一版，待更新啟用後再重整；資料保留已實測。
- GitHub Pages真實部署、手機安裝到主畫面、Google Sheet與AI出題服務尚未在本輪實測。
- 還原前會啟動備份下載，App不能確認使用者是否確實保存檔案，仍須人工保留。
- ZIP套件是程式與靜態網站快照，不含使用者正式學習資料；fixtures及匯出JSON都是合成驗收資料。

## 部署前與部署後

1. 使用者先在目前正式網站「設定→匯出備份」，每個有紀錄的裝置分別保存，確認檔案不是空檔。這些正式備份不需上傳到GitHub。
2. 使用者確認部署本候選版後，才提交並推送目前功能變更至現有repository；main推送會觸發GitHub Actions測試、build、部署。
3. 保持既有網址與Repository名稱，避免換origin造成瀏覽器資料看似消失。
4. 部署成功後在正式網址確認新版入口、原紀錄保留及一筆任務流程；更新未生效時待Service Worker啟用後重整，不清除網站資料。
5. 新版備份v3只能在支援v3的App還原。換裝置時先確認對方已更新，再匯入。

## 緊急回復方式

**不要直接把已升級v3資料庫的裝置導回只有v2資料層的程式，也不要為了回復畫面清除IndexedDB。**

本次已準備相容回復版：保留新版domain、Repository、v3 schema／遷移與備份保護；六個畫面／樣式檔使用基準commit的版本。暫時回到手動勾選學習任務，原有紀錄與study_task_id仍保留。

1. 遇到上線問題時先匯出v3備份，記下網址、裝置、操作步驟。
2. 經使用者確認後，使用`recovery-source-schema3.zip`的程式碼建立修正commit並由既有workflow部署，或由有權限者部署`recovery-site-schema3.zip`至同一Pages網址。
3. 等Service Worker更新後重整，再核對題庫、歷史測驗與任務勾選。必要時可於此相容回復版還原v3備份。
4. 修好問題後再部署支援v3資料的完整新版。若未來資料庫升至v4，需重新製作支援v4的回復版，不能沿用本套件降版。

候選與回復套件放在`out/release-20261012/`，包含SHA-256清單。`baseline-source.zip`只供程式比對，並非可直接回退到已升級裝置的版本。

本次尚未commit、push或部署。部署需使用者最後確認。
